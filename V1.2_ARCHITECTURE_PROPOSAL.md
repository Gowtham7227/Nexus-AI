## 1. Executive Summary

NexusAI v1.1.0 established a robust, deterministic, and highly accurate RAG baseline featuring:
- Adaptive RAG Optimizer (Dynamic query classification & parameter assignment)
- Hybrid RRF & Convex retrieval (ChromaDB + Sentence Transformers & BM25Okapi)
- In-process local Transformer Cross-Encoder (`cross-encoder/ms-marco-MiniLM-L-6-v2`)
- Deterministic Grounding & Verifiable Source Citations
- Multi-tier privacy guards, prompt-injection shields, and 100 MB OCR pipelines

NexusAI **v1.2.0** elevates the system to enterprise-grade production readiness by introducing three core observability and intelligence capabilities:
1. **End-to-End AI & RAG Observability (Telemetry)**: Fine-grained latency profiling across all retrieval, reranking, and generation stages without logging private document text.
2. **User Feedback & Evaluation Loop**: In-situ thumbs up/down evaluation with categorical feedback reasons linked directly to conversation messages.
3. **Tenant-Isolated Intelligent Response Caching**: Sub-millisecond response retrieval for repeated queries scoped with document fingerprints and model configurations.
4. **Real-Time AI/RAG Analytics Dashboard**: Enterprise visualization of system performance, query distributions, grounding quality, and latency telemetry.

## 3. Telemetry & Observability Architecture

### 3.1 Principles
- **Privacy-First**: No private document text, user prompts containing sensitive payloads, passwords, API keys, or raw JWTs are written to telemetry.
- **Tenant Scoped**: Every metric record is tagged with the authenticated user ID and filtered during querying.
- **Zero Latency Impact**: Telemetry write operations use low-overhead SQLite prepared statements.

### 3.2 Schema: `ai_request_metrics`
```sql
CREATE TABLE IF NOT EXISTS ai_request_metrics (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    request_id TEXT NOT NULL,
    conversation_id INTEGER,
    timestamp TEXT NOT NULL,
    query_type TEXT,
    optimizer_strategy TEXT,
    model TEXT NOT NULL,
    retrieval_ms REAL DEFAULT 0.0,
    chroma_ms REAL DEFAULT 0.0,
    bm25_ms REAL DEFAULT 0.0,
    fusion_ms REAL DEFAULT 0.0,
    cross_encoder_ms REAL DEFAULT 0.0,
    compression_ms REAL DEFAULT 0.0,
    ttft_ms REAL DEFAULT 0.0,
    generation_ms REAL DEFAULT 0.0,
    total_ms REAL DEFAULT 0.0,
    context_tokens INTEGER DEFAULT 0,
    output_tokens INTEGER DEFAULT 0,
    citation_count INTEGER DEFAULT 0,
    grounding_score REAL DEFAULT 0.0,
    document_count INTEGER DEFAULT 0,
    streaming INTEGER DEFAULT 0,
    cache_hit INTEGER DEFAULT 0,
    status TEXT DEFAULT 'success',
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_metrics_user_time ON ai_request_metrics(user_id, timestamp DESC);
CREATE INDEX IF NOT EXISTS idx_metrics_query_type ON ai_request_metrics(user_id, query_type);
CREATE INDEX IF NOT EXISTS idx_metrics_model ON ai_request_metrics(user_id, model);
```

## 5. Intelligent Response Cache Architecture

### 5.1 Cache Key Construction
To guarantee complete security and zero cross-tenant contamination, cache keys are constructed as a SHA-256 hash of:
$$\text{CacheKey} = \text{SHA256}(\text{user\_id} + "|" + \text{normalized\_query} + "|" + \text{doc\_fingerprint} + "|" + \text{model} + "|" + \text{optimizer\_ver})$$

- **Document Fingerprint**: Computed by hashing the filenames, sizes, and last modified timestamps of all currently selected documents for that specific user.
- **Cache Invalidation Lifecycle**:
  1. If any document is deleted or re-uploaded, the fingerprint changes immediately, causing a clean cache miss.
  2. A dedicated `invalidate_document_cache(user_id, filename)` helper purges matching entries.
  3. TTL-based automated eviction (default 86,400s / 24 hours).

### 5.2 Schema: `ai_response_cache`
```sql
CREATE TABLE IF NOT EXISTS ai_response_cache (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    cache_key TEXT UNIQUE NOT NULL,
    query_normalized TEXT NOT NULL,
    document_fingerprint TEXT NOT NULL,
    model TEXT NOT NULL,
    answer TEXT NOT NULL,
    citations_json TEXT,
    grounding_json TEXT,
    mode TEXT DEFAULT 'cloud',
    created_at TEXT NOT NULL,
    expires_at TEXT NOT NULL,
    hit_count INTEGER DEFAULT 0,
    last_accessed_at TEXT NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_cache_key ON ai_response_cache(cache_key);
CREATE INDEX IF NOT EXISTS idx_cache_user_expires ON ai_response_cache(user_id, expires_at);
```

## 6. Migration & Deployment Strategy
1. **Non-destructive SQLite Migrations**: Executed automatically in `init_auth_db()` upon backend startup.
2. **Backward Compatibility**: Fully backward-compatible with v1.1.0 client requests and existing database instances.
3. **Environment Toggles**: Caching and telemetry can be dynamically tuned via `.env`:
   - `RESPONSE_CACHE_ENABLED=true`
   - `RESPONSE_CACHE_TTL_SECONDS=86400`
   - `TELEMETRY_ENABLED=true`
