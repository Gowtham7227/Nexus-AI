## 4. Real Product Gaps & Technical Limitations

### 4.1 Document Intelligence
1. **Unstructured Table Flattening:** Tables in PDF, DOCX, and TXT files are converted into plain text strings. Table structure, row headers, and numeric column alignments are degraded, reducing retrieval accuracy for financial and tabular queries.
2. **Lack of Multimodal / Diagram Comprehension:** Figures, system architecture diagrams, charts, and image flowcharts inside documents are completely ignored during indexing.
3. **Restricted File Format Ingestion:** The engine currently ingests `.pdf`, `.txt`, `.md`, and `.csv`. Common enterprise formats such as `.docx`, `.xlsx`, `.pptx`, `.html`, `.json`, and `.rtf` are not natively supported.

### 4.2 RAG Reasoning Depth
1. **Single-Hop Retrieval Constraint:** The current engine performs a single retrieval step per query. Questions requiring chained reasoning (e.g., *"Find the project owner in Document A, then look up their department budget in Document B"*) cannot execute intermediate retrieval steps.
2. **Regex-Only Query Rewriting:** `QueryExpander` relies on basic keyword extraction and static regex rules. It lacks intent-driven HyDE (Hypothetical Document Embeddings) or multi-query semantic decomposition.
3. **Uniform Chunking Strategy:** Fixed 800-character chunking with 120-character overlap applies uniformly to prose, legal clauses, source code, and data tables without structural boundary awareness.

### 4.3 Citation & Attribution Granularity
1. **No Visual PDF Snippet Bounding Boxes:** Citations reference document name and page number (`ss-high.pdf [Page 1]`), but the frontend cannot highlight the exact bounding box rectangle on the PDF viewer canvas.
2. **Lack of Conflicting Evidence Detection:** When multiple documents state conflicting facts (e.g., Doc A says Q4 revenue was $10M while Doc B says $12M), the system generates an answer without explicitly flagging the factual contradiction.

### 4.4 AI Routing & Model Strategy
1. **Static Cloud/Local Switch:** The execution mode is a static binary setting (Cloud vs Local). The system cannot dynamically route a simple query to a fast local model while routing an intricate multi-document analytical question to Gemini 3.5.
2. **No Cost & Token Budget Tracking:** Token counts are estimated via character heuristics (`len(text) // 4`), and monetary cost per query/session is not calculated or tracked.

### 4.5 Enterprise Security & Workspace Collaboration
1. **No Multi-User Team Workspaces:** All document collections and chats are isolated to single user IDs. There is no concept of shared team workspaces, project folders, or organizational access tiers.
2. **Single-Node SQLite Storage:** SQLite with WAL mode is optimal for single-instance deployments, but does not support multi-instance distributed deployments or horizontal scaling.

## 6. User Experience & Frontend Audit

1. **Dashboard:** Displays recent documents and telemetry stats cleanly. Lacks quick-start template prompts for common document queries (e.g., "Summarize Key Metrics", "Find Action Items").
2. **Documents Page:** Document uploading, selection, and deletion work reliably with async status polling (2.5s interval). However, document search is an in-memory client-side filter; large document libraries (>100 files) will require server-side pagination and sorting.
3. **Chat Page:** SSE streaming operates smoothly with Markdown tables and code blocks. Thumbs up/down feedback modal collects structured reasons. A floating "Scroll to Bottom" button is missing when users scroll up to inspect citations during active generation.
4. **Analytics Page:** Displays latency breakdowns, KPI cards, query type distributions, feedback stats, and cache purge controls. Lacks custom date range pickers and CSV export capability.
5. **Settings Page:** Clean Cloud vs Local mode toggle. Lacks a live "Test Ollama Connection" ping button to verify local LLM responsiveness before saving.
6. **Mobile / Responsive Layout:** Sidebar collapses gracefully on small viewports, but table citations require horizontal scrolling on screens narrower than 480px.

## 7. Security & Privacy Audit Findings

1. **Pre-Retrieval Authorization:** Verified across all endpoints (`/chat`, `/chat/stream`, `/document-summary`, `/documents/{filename}/file`, `/documents/{filename}`, `/feedback`, `/analytics`). Users cannot access, query, or delete other users' documents or cached responses.
2. **Multi-Tenant Response Cache:** Cache keys enforce SHA-256 multi-tenant isolation combining `user_id`, `normalized_query`, `content_hash`, and model version. Zero cross-user cache exposure.
3. **Prompt Injection Defense:** Adversarial instruction override patterns (`SYSTEM OVERRIDE: ...`) are quarantined inside `<retrieved_document>` XML tags, preventing context escape.
4. **Output Privacy Guard:** Regex-based sanitization successfully intercepts and redacts leaked API keys, tokens, and credentials from LLM responses before delivery to client.
5. **JWT Token Validation:** Missing tokens, invalid signatures, tampered payloads, expired timestamps, and `alg: none` header bypass attacks are strictly rejected with HTTP 401.
6. **Upload Gateway:** Path traversal attempts, fake PDF headers, and executables are blocked with HTTP 400/415. 100MB upload limits strictly enforced.

## 10. v1.3 Feature Candidates

The following feature candidates are identified based on empirical product gaps. *(Candidates are listed neutrally without rankings).*

---

### Candidate A: Table-Aware & Structured Document Extraction
- **Problem:** Financial reports, data sheets, and tabular data in PDFs/DOCX lose column/row associations during plain-text extraction.
- **Evidence:** Queries regarding specific numerical rows or column comparisons yield partial or degraded answers.
- **Technical Complexity:** Moderate-High. Requires integration of structured PDF table extractors (e.g., `pdfplumber`, `unstructured`, or `Camelot`) and markdown table serialization.
- **Dependencies:** `pdfplumber` / `pypdf`, table chunking strategy.
- **Security Implications:** Input validation required for oversized table structures to prevent memory exhaustion.
- **Expected Measurable Benefit:** +30-40% accuracy improvement on structured tabular and financial queries.
- **Risk:** Increased indexing time per document page (+200-500ms).

---

### Candidate B: Multi-Hop Reasoning & Iterative Retrieval Engine
- **Problem:** Complex queries requiring sequential deduction across multiple documents fail in single-step retrieval.
- **Evidence:** Comparison test queries requiring chained facts have lower grounding scores (0.62-0.75 vs 1.0 for factual).
- **Technical Complexity:** High. Requires query plan decomposition, intermediate reasoning verification, and iterative retrieval loops with strict step bounds (max 3 hops).
- **Dependencies:** Adaptive RAG Optimizer query planner, intermediate context aggregator.
- **Security Implications:** Step-count bounds required to prevent infinite reasoning loops or excessive API consumption.
- **Expected Measurable Benefit:** Enables cross-document analytical synthesis and chained QA.
- **Risk:** Additional latency (+500ms - 2000ms) for multi-hop queries.

---

### Candidate C: Intelligent Dynamic AI Model Router
- **Problem:** Cloud vs Local model is a global manual toggle. Simple factual queries waste cloud API quota; sensitive documents cannot be dynamically restricted to local processing.
- **Evidence:** Telemetry shows 45% of queries are `simple_factual` that could execute locally in <500ms without cloud transmission.
- **Technical Complexity:** Moderate. Requires query intent + privacy classification layer to dynamically select Gemini 3.5, Gemini Flash, or local Qwen.
- **Dependencies:** `model_provider.py`, `rag_optimizer.py`, local Ollama health prober.
- **Security Implications:** Privacy-flagged documents automatically enforce local-only routing.
- **Expected Measurable Benefit:** -40% cloud API costs, reduced latency for simple queries, guaranteed local isolation for confidential files.
- **Risk:** Local model unavailability if Ollama daemon is offline.

---

### Candidate D: Visual PDF Citation Bounding-Box Overlay & Previewer
- **Problem:** Citations show page numbers, but users must manually scroll and locate the exact sentence in long PDFs.
- **Evidence:** User feedback indicates desire to verify source text directly inside the UI without opening external PDF readers.
- **Technical Complexity:** Moderate. Requires capturing chunk bounding box coordinates (`x0, y0, x1, y1`) during PyMuPDF extraction and rendering highlights in a frontend PDF viewer (e.g., `react-pdf` / `pdfjs`).
- **Dependencies:** PyMuPDF bbox metadata extractor, `react-pdf` component.
- **Security Implications:** None (coordinates derived from authorized document text).
- **Expected Measurable Benefit:** Dramatic UX improvement for auditability and compliance verification.
- **Risk:** Increased metadata storage size in ChromaDB.

---

### Candidate E: Semantic Response Caching (Cosine Similarity)
- **Problem:** Current response cache requires exact normalized string match. Semantically identical questions (*"What is the revenue for Company A?"* vs *"Tell me Company A's revenue"*) result in cache misses.
- **Evidence:** Telemetry indicates near-identical queries with minor word order variations bypass the 0.037ms cache.
- **Technical Complexity:** Moderate. Requires caching query embeddings and performing cosine similarity lookup (threshold >= 0.96) within the user's isolated document fingerprint pool.
- **Dependencies:** `embedding_model`, SQLite vector extension or lightweight in-memory cosine index.
- **Security Implications:** Tenant isolation and document content hash matching must remain strictly enforced before semantic lookup.
- **Expected Measurable Benefit:** Cache hit rate projected to increase by 25-35%, cutting average query latency and LLM costs.
- **Risk:** Potential edge-case semantic false positives if threshold is configured too low (<0.95).

---

### Candidate F: Cost & Token Budget Tracking with Exportable Reports
- **Problem:** Analytics displays latency and token estimates, but does not provide monetary cost calculation, usage budgets, or exportable compliance reports.
- **Evidence:** Enterprise evaluators require cost-per-department and exportable CSV audit logs.
- **Technical Complexity:** Low-Moderate. Requires model price mapping table ($/1M input/output tokens), daily aggregation queries, and CSV export endpoint.
- **Dependencies:** `ai_request_metrics` table, frontend export action.
- **Security Implications:** Financial metrics restricted to authenticated user.
- **Expected Measurable Benefit:** Full transparency into AI infrastructure operational costs.
- **Risk:** None.

---

### Candidate G: Modular Backend Architecture Refactoring
- **Problem:** `main.py` is 2,996 lines, creating maintenance friction and coupling unrelated concerns.
- **Evidence:** Code analysis shows route definitions, background tasks, and utility functions mixed together.
- **Technical Complexity:** Low-Moderate. Refactor into FastAPI `APIRouter` modules (`routers/auth.py`, `routers/chat.py`, `routers/documents.py`, `routers/analytics.py`).
- **Dependencies:** None.
- **Security Implications:** Ensure all route dependencies (`get_current_user`) remain strictly attached to router endpoints.
- **Expected Measurable Benefit:** Improved code maintainability, testability, and developer velocity.
- **Risk:** Regression if route paths or middleware bindings shift during refactoring.

## 11. Technical Dependencies & Constraints

1. **RAG Algorithm Frozen Baseline:** Core v1.1 / v1.2 retrieval algorithms (Chroma + BM25 + RRF + Cross-Encoder) must remain intact as the validated baseline.
2. **Backward Compatibility:** All existing endpoints (`/chat`, `/chat/stream`, `/upload`, `/documents`, `/analytics`, `/feedback`) must maintain existing request/response contracts.
3. **Database Migration Safety:** All schema modifications in SQLite must use non-destructive `IF NOT EXISTS` or `ALTER TABLE ... ADD COLUMN` migration scripts.
4. **Multi-Tenant Isolation Integrity:** Pre-retrieval authorization must precede any new feature (e.g., semantic caching, multi-hop reasoning, table extraction).

## 14. Explicitly Deferred Items

The following items are deferred beyond v1.3.0:

3. **Audio / Video Multimodal Transcription (Whisper):** Deferred to keep deployment lightweight and focused on document intelligence.
4. **Third-Party SaaS Integrations (Slack / Notion / Google Drive):** Deferred until core enterprise workspaces and RBAC are standardized.
